# Standalone FIQA analysis pipeline

These scripts replace the analysis notebooks with command-line programs. They
all read the dynamic JSON configuration created by `setup_project.py` and do not
contain personal Google Drive paths or fixed checkpoint filenames.

## Required repository layout

```text
fiqa-demographic-analysis/
├── config/
│   └── runtime_config.json       # generated, do not commit personal paths
└── scripts/
    ├── setup_project.py
    ├── extract_scores.py
    ├── pipeline_common.py
    ├── run_eda.py
    ├── train_models.py
    ├── optimize_models.py
    ├── correlation_analysis.py
    ├── regression_analysis.py
    ├── explainability.py
    ├── demographic_consistency.py
    └── run_pipeline.py
```

`pipeline_common.py` is required by all analysis scripts and must be uploaded to
the same `scripts/` directory.

## Execution order

```bash
python scripts/setup_project.py ...
python scripts/extract_scores.py --config config/runtime_config.json
python scripts/run_eda.py --config config/runtime_config.json
python scripts/train_models.py --config config/runtime_config.json
python scripts/optimize_models.py --config config/runtime_config.json --mode quick
python scripts/correlation_analysis.py --config config/runtime_config.json
python scripts/regression_analysis.py --config config/runtime_config.json
python scripts/explainability.py --config config/runtime_config.json
python scripts/demographic_consistency.py --config config/runtime_config.json
```

After score extraction, stages 02–08 can also be run sequentially with:

```bash
python scripts/run_pipeline.py \
  --config config/runtime_config.json \
  --optimization-mode quick
```

For the final analysis, replace `quick` with `full`.

## Stage dependencies

- `run_eda.py` reads the merged dataset generated by `extract_scores.py`.
- `train_models.py` saves the identity-disjoint train/test split.
- `optimize_models.py` reuses that exact split and selects the final model by
  identity-aware cross-validation RMSE.
- `correlation_analysis.py` produces the RQ2 univariate association tables.
- `regression_analysis.py` consumes the RQ2 table and produces RQ3 adjusted
  effects with HC3 inference.
- `explainability.py` uses the final tuned model and unchanged test split, then
  combines SHAP/permutation results with RQ2 and RQ3 where available.
- `demographic_consistency.py` evaluates group-specific effects and uses formal
  FDR-adjusted feature-by-group interaction tests as its primary heterogeneity
  evidence.

## Dynamic input handling

The merged dataset is resolved in this order:

1. `--data /path/to/file.csv`;
2. `merged_data_file` in the runtime JSON, when present;
3. `<results_dir>/01_score_extraction/diveface_fiqa_merged.csv`;
4. the legacy `<project_dir>/diveface_fiqa_merged.csv` location.

All output paths are derived from `results_dir` and `models_dir` in the runtime
configuration.

## Development smoke test

Use quick optimization, omit XGBoost, and skip SHAP for a faster structural test:

```bash
python scripts/run_pipeline.py \
  --config config/runtime_config.json \
  --optimization-mode quick \
  --skip-xgboost \
  --skip-shap
```
